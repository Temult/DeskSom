# Discovery Resilience R1 integration decisions

Date: 2026-10-17. Integration baseline: the canonical AI-first public-source **v0.2.0-rc.2** tree at commit `bcdf6d13ea63a0bb467f91a760a8e7b05e381c88`. The existing v0.2 engineering ancestor was preserved. Source donor: `workspaces/discovery-resilience-20261017`; its 8-file ZIP and all QUALIFICATION.json member digests were verified before use.

## Accepted

- `catalog.mjs`: 24 compact upstream tool descriptions plus unchanged names, schema objects, operation semantics, non-UI metadata, and existing allow/deny tool selection; preserve unknown future descriptions. Nine file-mutation/host-execution tools are explicitly marked `readOnlyHint:false`.
- `catalogCapabilities`: immutable server-side snapshot of 25 advertised tool names including `desksom_status`, file-mutation names and host-execution names, truthful summary flags, and explicit limits on what the server can observe about ChatGPT.
- The donor's `catalog.test.mjs`, its modern/legacy live integration scenario, and `CHAT_DISCOVERY_DIAGNOSTIC.md` with six distinct outcome categories.
- Concise MCP server instructions warning that advertising a tool cannot establish whether an individual chat can invoke it.

## Modified in rebase

- Insert `prepareCatalog` in the existing v0.2 broker instead of replacing that broker. Preserve the instance, installationId and sourceFingerprint fields and all source-sealed installation/credential/task gates.
- Retain `catalogSha256` as SHA-256 over the **24 upstream** definitions; retain `tools` as the **24 upstream** tool count. Add `advertisedToolCount:25` plus `advertisedCapabilities`, which include the identity tool.
- Expand the donor integration fixture to assert v0.2 instance/installation/source identity and allow a longer startup on slower Windows hosts. Keep tests isolated with an ephemeral loopback port and synthetic bearer, never the production tunnel.
- Preserve status, operation consent, no-blind-replay semantics, source manifest integrity, and the AI-first installer. The generated `engine-overlay.json` used in local tests is excluded from public source and regenerated by each recipient's installer.
- Document real ChatGPT metadata refresh behavior. The public MCP server's `ttlMs:0` does not refresh an approved ChatGPT tool-action snapshot.

## Rejected or deferred

- The donor's v0.1.3-derived `broker.mjs` as a wholesale replacement: it omits v0.2 installation identity and source-bound diagnostics.
- The donor's top-level README and QUALIFICATION.json as shipping source: they describe an older, donor-only release. Retain their original sealed bytes in the donor workspace as provenance.
- Any assertion that shorter descriptions **cause** all ChatGPT conversations to expose write tools. Selection and authorization remain client/workspace-specific and currently unproven. Tool description reduction is a measurable discovery signal, not a proven repair.
- Any live production cutover, task restart, tunnel reconfiguration or permission bypass during integration. Those require a separately reviewed maintenance seam and ChatGPT-side check.

## Qualification interpretation

The isolated integration confirmed 25 tools in both protocol catalogs, total description text of 2,238 characters, all original tool names and input schemas, modern and legacy tool enumeration, advertised capability status consistency, real sandboxed-to-disposable-path write/edit/read, a bounded shell invocation, and unauthenticated rejection. The operation ran using a synthetic local bearer and not an OpenAI account token.

Both a problematic existing ChatGPT conversation and a fresh conversation must still be compared **after owner-approved deployment**, holding host, server boot ID and catalog hash constant. That test, not the source code, will establish whether client-side inconsistency is present. Detailed procedure: [CHAT_DISCOVERY_DIAGNOSTIC.md](CHAT_DISCOVERY_DIAGNOSTIC.md).

Reference for published app action snapshots and owner/admin refresh: https://help.openai.com/en/articles/12584461-connecting-custom-mcp-servers-in-chatgpt
